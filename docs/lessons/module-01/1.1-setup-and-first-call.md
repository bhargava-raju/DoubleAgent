## Concepts

### uv and `pyproject.toml`

| C# / .NET | Python |
|-----------|--------|
| `dotnet` CLI | `uv` |
| `.csproj` | `pyproject.toml` |
| `PackageReference` | `[project] dependencies` (add with `uv add <pkg>`) |
| test/analyzer packages | `[dependency-groups] dev` (add with `uv add --dev <pkg>`) |
| `packages.lock.json` | `uv.lock` (committed) |
| `bin/` + restored packages | `.venv/` (git-ignored) |
| `dotnet run` | `uv run doubleagent ...` (from `[project.scripts]`) |

Open `pyproject.toml` and find each row above. The `[tool.*]` sections configure pytest, ruff and pyright,
much like an `.editorconfig` or `Directory.Build.props`.

> Practice (optional): in a scratch folder, run `uv init --package demo` then `uv add httpx` and read what changed.
> That's how this repo's scaffold was created.

### Modules and packages

A `.py` file is a **module**; a folder with `__init__.py` is a **package**. `src/doubleagent/llm.py` is imported as
`doubleagent.llm`. You import **names**, not whole namespaces: `from doubleagent.llm import ask`.

### Type hints are checked by a tool, not at runtime

```python
def ask(question: str, *, model: str, system: str | None = None) -> Answer: ...
```

- `str | None` ≈ `string?`. `list[str]` ≈ `List<string>`.
- The bare `*` makes everything after it **keyword-only**: callers must write `model="..."`. Use it for anything
  that's easy to mix up (two ints, two strings).
- Python ignores these hints at runtime. **pyright** (and Pylance in VS Code) checks them, like the C# compiler.
  **Pydantic** is the exception: it validates at runtime, so we use it at the edges (config, API data, LLM output).

### `async`/`await`

```python
async def ask(...) -> Answer:            # async Task<Answer> AskAsync(...)
    response = await client.messages.create(...)

asyncio.run(main_async())                # async Task Main()
```

The gotcha for C# developers: **coroutines are cold**. Calling `ask(...)` without `await` returns a coroutine
object and does nothing (pyright warns you). C# `Task`s start running immediately.
`async with AsyncAnthropic() as client:` ≈ `await using var client = ...;`: it closes the HTTP connections.

### Settings with pydantic-settings

`BaseSettings` fields bind from environment variables (case-insensitive) and `.env`, and are validated at startup,
like `IOptions<T>` with `ValidateOnStart()`. `SecretStr` hides the value in logs; call `.get_secret_value()` to use it.
`@lru_cache` on a zero-argument function turns it into a lazy singleton.

### LLM foundations

- **Tokens.** Models read and write tokens (roughly ¾ of an English word). You pay per input and output token,
  and `response.usage` tells you how many. `max_tokens` caps the *output*; hit it and the answer is cut off
  (`stop_reason == "max_tokens"`).
- **Context window.** The maximum tokens per request, input plus output (1M for current Claude models).
  The API is **stateless**: every call resends the whole conversation, so long chats cost more each turn.
- **Messages API.** One request = model + optional `system` prompt + `messages` list → a response whose
  `content` is a **list of blocks** (`text`, `thinking`, later `tool_use`). Current models think first, so
  don't assume `content[0]` is the answer.
- **Prompting.** The `system` prompt sets role, rules and output format; the user message carries the task.
  Be specific about what "good" looks like; the model can't read your mind.
- **Hallucination.** A model generates plausible text; it doesn't look things up unless you give it the facts
  (Module 2) or tools (1.2). Try asking about a made-up supplier and see what happens.
